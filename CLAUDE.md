# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

Личный учебный репозиторий: владелец шаг за шагом изучает Python, чтобы научиться работать с ИИ-агентами (план в `hello.py`: окружение → Python → Claude Code → субагенты → Agent SDK). Владелец знаком с C, поэтому комментарии в коде сравнивают Python с C. Каждый «день» добавляет отдельные учебные скрипты с именами `dayN_<тема>.py`, прогресс отмечается в `README.md`.

Это учебный проект, поэтому код должен быть простым и наглядным. Новые понятия поясняй короткими комментариями на русском прямо рядом с кодом, в том же стиле, что уже есть. Не переписывай файлы прошлых уроков в «более правильный» код: они специально показывают постепенное развитие. Например, в `day2_functions.py` используется явный цикл, а в `todo_utils.py` для того же списковое включение (list comprehension).

## Окружение и команды

- Python 3.15 в локальном виртуальном окружении `.venv/`. Оно, как и `__pycache__/`, исключено из git.
- Запуск скрипта: `.venv\Scripts\python.exe имя_файла.py`. Можно сначала активировать окружение командой `.venv\Scripts\Activate.ps1`, а потом писать просто `python имя_файла.py`.
- Установка зависимостей: `.venv\Scripts\python.exe -m pip install -r requirements.txt`. Сейчас из зависимостей только `rich` и то, что она подтягивает.
- `requirements.txt` храни в UTF-8. В Windows PowerShell 5.1 команда `pip freeze > requirements.txt` сохраняет файл в UTF-16, и git считает его бинарным. Правильно так: `.venv\Scripts\python.exe -m pip freeze | Out-File -Encoding utf8 requirements.txt`.
- Тестов, линтера и сборки нет. Каждый скрипт запускается напрямую.
- `hello.py` и `day2_errors.py` ждут ввода с клавиатуры через `input()`. `day2_errors.py` в конце переспрашивает, пока не получит число. Сам их не запускай — это делает владелец вручную в своём терминале.

## Структура

- Почти все файлы `dayN_*.py` — самостоятельные примеры. Общий код лежит только в `todo_utils.py`: это небольшой модуль с функциями для сквозного примера «список дел» (`format_task`, `open_tasks`, `count_done`). Его импортируют `day2_main.py` и `day2_rich.py`.
- Во всех уроках данные хранятся одинаково — как список словарей: `{"title": str, "done": bool, "owner": str (необязательно)}`. Необязательное поле код читает через `.get("owner", "-")`.
- `todo.json` создаётся автоматически: `day2_main.py` перезаписывает его в той папке, откуда запущен скрипт. Поэтому скрипты нужно запускать из корня репозитория.

## Как со мной работать

- Я руководитель IT-проектов и учусь управлять разработкой с ИИ-агентами. Код читаю, но сам почти не пишу. Объясняй простым языком, что делаешь и зачем.
- Отвечай на русском.
- Перед изменениями кратко скажи план. После — перечисли, какие файлы изменены и что не сделано.
- Не делай push без моей просьбы. Коммить только после того, как код запущен и работает.
- Одна задача — один коммит. Сообщение коммита пиши на русском.
- Если предлагаешь мне команду для запуска, пиши её для PowerShell на Windows.
- Если задача неясна или есть несколько вариантов, спроси, а не угадывай.
- Если задача требует больше 2–3 попыток или уходит в сторону от исходной цели, остановись и спроси меня, стоит ли продолжать.
- Отложенные задачи (бэклог) и принятые решения записывай в `NOTES.md`: у задачи укажи серьёзность, у решения — дату и причину. Перед новой задачей загляни туда, а сделанное из бэклога убирай.
