# Приёмка работы

Цель: руководитель проекта, который читает код, но сам почти не пишет, должен понять, что изменилось и работает ли это. Пиши по-русски, простым языком.

Во время приёмки ничего не исправляй и не коммить. Только проверяй и сообщай.

## Шаг 1. Что изменено

- Выполни `git status --short` и `git diff --stat`.
- Покажи список изменённых, новых и удалённых файлов, по одной строке о каждом.
- Если изменений нет, так и скажи и закончи приёмку.

## Шаг 2. Объяснение изменений

- Прочитай `git diff` и новые файлы целиком.
- В 3–6 пунктах объясни, что теперь делает программа иначе и зачем. Не пересказывай код построчно.
- Если что-то в изменениях выглядит странно или выходит за рамки задачи, отметь это отдельно.

## Шаг 3. Запуск изменённых скриптов

- Запускай через `.venv\Scripts\python.exe имя_файла.py` из корня репозитория.
- Скрипты с `input()` (ждут ввода с клавиатуры) НЕ запускай. Найди их поиском `input(` среди изменённых `.py`-файлов и перечисли пользователю: «эти скрипты проверьте вручную».
- Модули без собственного запуска (например, `todo_utils.py`) проверяй через скрипты, которые их импортируют.
- Если в выводе есть `Traceback`, это проблема.

## Шаг 4. Крайние случаи (3–5 штук)

**Защита данных.** Перед проверками, которые меняют `todo.json`, скопируй его во временную папку (scratchpad). После проверок верни копию на место. Если файла до проверок не было, удали созданный. Обязательно сообщи, что данные восстановлены.

Выбери случаи, подходящие к изменённому скрипту. Для `day3_todo_cli.py`, например:
- пустой ввод: `add ""` и `add` без текста;
- неверный номер: `done 0`, `done 999`, `done abc`;
- неизвестная команда: `foo`;
- спецсимволы: `add "[bold]тест[/bold]"` — текст должен показаться как есть, без оформления.

Хорошее поведение при ошибке: понятное сообщение на русском, код выхода 1, нет `Traceback`.

## Шаг 5. Итоговая таблица

| Проверка | Результат | ОК/Проблема |
|---|---|---|
| Запуск `list` | Таблица из 3 задач | ОК |
| `done 999` | Traceback IndexError | Проблема |

В таблицу входят все запуски из шагов 3 и 4.

## Шаг 6. Вердикт

- Все проверки ОК → **«Можно коммитить»**.
- Есть хоть одна проблема → **«Нужно исправить: …»** и список проблем, коротко.
- В конце отдельно перечисли, что проверить вручную (скрипты с `input()`).
- Сам не коммить и не исправляй, даже если вердикт положительный.
